Process Algebra is the center execution semantics of Garden. It describes how typed operations compose. AAP is the
process compiler/router: it chooses the minimum sufficient architecture subgraph, assurance depth, resources,
authorities and fallbacks for the requested operation. The Universal Per-Step Control Loop governs every meaningful
transition inside the compiled process.

Canonical execution spine:

    → ProcessPlan

Universal TransitionStep loop:

  Observe
    → Understand / Type
    → Compare
    → Reason
    → candidate generation
    → Select
    → Guard selected transition
    → Execute / Derive / Communicate
    → Observe resulting state
    → Compare expected vs actual
    → Update / Correct / Retry / Replan / Research / Escalate / Learn / Terminate.

A cheap pre-selection constraint filter may remove obviously inadmissible candidates before Select. The canonical
effect gate still evaluates the selected candidate before any effect. This resolves the conceptual shorthand
"Guard → Select" without permitting an unguarded selected action.

Meaningful transition boundary:

activation. A transition is meaningful when it creates or materially changes persistent/canonical state, external
effects, a decision/branch, authority, epistemic status, resource commitment, consequential communication, or another
declared process boundary. Lower implementation operations inherit the enclosing verified contract unless separately
elevated by AAP, risk or policy.

CORE PRINCIPLE
Every meaningful state transition in Garden is a controlled step: observed, typed, compared, reasoned, selected,
guarded, executed/derived/communicated, observed again, compared again and recorded.

This does not mean every transition runs the full heavyweight Reason/Proof/Safety stack. Every meaningful step carries
the cheap universal kernel at a baseline tier and escalates only when required by consequence, irreversibility,
authority, novelty, uncertainty, sensitivity, dependency impact, disagreement or applicable hard policy.

CANONICAL UNIVERSAL STEP

  Current State
       ↓
  Observe
       ↓
  Understand / Type
       ↓
  Compare actual vs expected / desired
       ↓
  Reason
       ↓
  Generate candidate transitions
       ↓
  Select candidate
       ↓
  Guard selected candidate
       ↓
  Act / Derive / Communicate
       ↓
  Observe resulting state
       ↓
  Compare expected vs actual
       ↓
  Record / Update / Learn / Escalate
       ↓
  Next State

A pre-selection constraint filter may run before Select to remove obviously inadmissible candidates. It does not
replace the final effect guard on the selected transition.

COMPARE AS A UNIVERSAL CONTROL FLOW

  two typed states/claims/candidates + comparison context
  → determine applicable comparison dimensions
  → retrieve relevant evidence, constraints and dependency context
  → compare each applicable dimension
  → preserve uncertainty, conflicts, materiality and incomparability
  → produce ComparisonResult
  → feed Reason / Select / Explain / Research / Escalate as applicable.

Level 3 owns the COMPARE(...) signature, ComparisonResult field contract and ComparePolicy implementation details.
TechnicalRef: [T-COMPARE-CONTRACT]

REASON AS A TIERED UNIVERSAL PRIMITIVE

  R0 — Transition Sanity
       Does the transition follow at the declared abstraction? Is it obviously contradictory or inadmissible?
       Intended cost: extremely cheap.

  R1 — Local Reasoning
       Choose among a small local candidate set; cheap.

  R2 — Contextual Reasoning
       Use knowledge, dependencies, constraints and multiple alternatives; moderate.

  R3 — Deep Reasoning
       Theory selection/composition, simulation, mathematical analysis, adversarial comparison and broader search;
       expensive.

  R4 — Critical Reasoning
       Maximum bounded assurance appropriate to the scope, independent challenge and required governance/human
       escalation; highest planned tier.

Reason is logically present at every meaningful step, but the active tier is selected by AAP. A tier is an assurance
depth, not a claim that real compute cost follows a universal fixed multiplier.

VERITY / PROOF TIERS

  V0 — structural/type/invariant sanity.
  V1 — ordinary validation.
  V2 — evidence/dependency/assumption checking.
  V3 — independent/deeper verification.
  V4 — formal/high-assurance verification appropriate to the critical scope.

SAFETY TIERS

  S0 — fast boundary/sanity guard.
  S1 — local constraint check.
  S2 — environment and consequence verification.
  S3 — independent/deeper trajectory, human-presence or domain safety validation where applicable.
  S4 — maximum bounded K0P/emergency-readiness/high-criticality assurance for the declared scope.

minimum floor independently from the operation and its obligations. Hard predicates may force a minimum tier regardless

REASON AND COMPARE OCCUR ON BOTH SIDES OF EFFECTFUL ACTION

  BEFORE
    current state
      → compare actual/desired and candidate alternatives
      → reason
      → select
      → guard.

  AFTER
    effect
      → observe
      → compare expected/actual
      → reason about material discrepancy
      → accept, correct, retry, replan, research, escalate, learn or terminate.

A non-effectful pure derivation still has a typed comparison/reasoning/verification closure appropriate to its class;
an external-world observation step additionally closes the expected-versus-observed loop.

RECURSIVE CONTROL MODEL

  S_t
    --Observe--> O_t
    --Compare+Reason--> D_t
    --Select+Guard--> A_t
    --Execute--> S_(t+1)
    --Observe+Compare--> E_t

where:
  S_t       = current state;
  O_t       = observation;
  D_t       = decision/candidate selection;
  A_t       = authorized transition/effect;
  S_(t+1)   = resulting state;
  E_t       = typed discrepancy between expected and observed result.

A material E_t may route to:
  CORRECT | RETRY | REPLAN | RESEARCH | ESCALATE | LEARN | TERMINATE.

operation inherits the enclosing transition contract unless it crosses a declared effect, state, authority, epistemic,
resource, persistence, audit or risk boundary that requires its own TransitionStep.

Status: RATIFIED / ADDITIVE / integrated into Engine.Orchestrate.
Primary principle:
For every requested operation, Garden determines which engines/capabilities/domains activate; which checks are mandatory
or optional; required verification depth; resource/time limits; human approval requirements; and fallback on
uncertainty/failure/timeout. Safety emergencies may substitute pre-authorized emergency paths for ordinary deliberation

 CONSEQUENCE
 IRREVERSIBILITY

    Use       : Routine, familiar, low-consequence and reversible work.
    Minimum   : Cheap retrieval/type/policy checks; fresh validated cache reuse is permitted.
