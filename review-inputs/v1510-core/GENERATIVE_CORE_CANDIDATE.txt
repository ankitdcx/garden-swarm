STATUS
Noncanonical review material only. No authority, proof, implementation, certification or Garden promotion.

GOAL
Compress Garden by expressing repeated semantics once in GSL, while keeping the current ~48 human-readable architecture-object modules as the navigation/explanation view. The human modules remain recognizable; their repeated internals become generated/specialized from a small basis.

EXISTING GSL FOUNDATION — MUST REMAIN, NOT DUPLICATE
Pillars: Existence, Change, Agency, Law, Value, Frame.
Core Objects: TIME, SPACE, THING, EVENT, ACTION, AGENCY, RULE, VALUE, CONTEXT, CLAIM.
Existing cross-cutting semantic/control families already cover state, observation, authority, resource, provenance, causality, dependency, conflict, uncertainty, decision, validity, comparison and reasoning.
Existing admitted algebras remain Process, Policy, Decision, Conformance, Evidence and Bridge.

PROPOSED ABSTRACTION PILLARS — HUMAN QUESTIONS, NOT NEW ONTOLOGY
1 IDENTITY — what is it?
2 CONDITION — what state/validity/context is it in?
3 CONNECTION — what is it related/bound to?
4 BEHAVIOR — how does it operate/change/transform?
5 CONSTRAINT — what contract/rule/authority/evidence/safety boundary applies?
6 REPRESENTATION — how is the accepted meaning rendered for human/machine/math/runtime use?

PROPOSED SEVEN CORE FORMS — GSL-NATIVE DESIGN FORMS
A CONSTRUCT: stable typed design/semantic identity; normally an existing THING/ARTIFACT/ArchitectureObject.
B CONTRACT: purpose plus inputs/outputs/preconditions/postconditions/effects/authority/consent/hard limits/evidence/proof/failures/resources/termination/dependencies/invalidators.
C STATE: typed condition, lifecycle, validity and status over time/context.
D RELATION: owner-qualified directional binding/relationship including scope, boundary and non-transitivity semantics.
E PROCESS: state-changing/deriving/communicating behavior built from existing Process Algebra and ACTION/EVENT transitions.
F RULE: condition to obligation/permission/prohibition/constraint/derivation using existing GSL RULE; protected owner remains controlling.
G PROJECTION: representation of accepted semantics into a human view, machine schema, receipt, registry entry, API, mathematical/operator representation, executable test, etc.

Architecture object/module = Construct + Contract + State + Relations + Processes + Rules + Projections.
Function = Contract + Process.
Lifecycle = State + Process + Rule.
Schema = machine Projection of accepted semantic structure; stable SchemaID remains owner/version bound.

Binding = Relation + Context + Contract/Rule.
Plan = Process + Contract + State.
Assessment = Process + Contract + result State/Projection.
Invariant = Rule or accepted derived Rule instance.

Reference architecture/profile = Construct + Contract + Context specialization + Relation bindings + Process + Rule + Projection.
Domain = Construct containing typed claims/rules/theories/evidence/bindings and domain contracts.
Existing GSL Context/Evidence/Claim/Event/Action/Agency/Value/Rule are reused directly, never duplicated by abstraction.
