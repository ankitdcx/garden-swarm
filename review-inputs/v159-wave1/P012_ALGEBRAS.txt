ALGEBRA ADMISSION TEST
An architectural mechanism is an Algebra only when it defines reusable typed operands, operators, composition/closure laws, identity/error/unknown behavior and interaction rules that eliminate duplicated semantics.
Every admitted Algebra has a machine-readable AlgebraSignature. A law is declared only where it actually applies; Garden does not invent identity, associativity, commutativity or idempotence merely for symmetry.
Concrete AlgebraSignature instances resolve through REG-ALGEBRA-001. A law omitted from an instance is not assumed.

EVIDENCE COMPOSITION ALGEBRA
Purpose: reusable dependence-aware composition semantics for empirical evidence without turning Evidence into Proof.
Artifact: EvidenceComposition; EvidenceDependenceModel may represent common-source, causal, methodological, statistical or conditional dependence; it is not restricted to binary independence or one universal correlation coefficient. Cycles are allowed where the declared dependence model permits them.
Core flow:
  evidence inputs + dependence/context model
  -> assess dependence
  -> corroborate / contradict / condition
  -> preserve uncertainty and source dependence
  -> typed combined/conflict/conditional evidence state.
Correlated/shared-source evidence cannot be counted as independent because it appears in multiple records. Dependence-aware composition uses the declared valid model; no arbitrary universal down-weight. Probability/confidence output only when a calibrated probabilistic model justifies it. Proof may verify formal calculation/model-consistency; Knowledge/Research/Reason own empirical credibility/source validity/applicability.

FUTURE ALGEBRA BOUNDARY
Explanation, Authority, Dependency and Resource remain non-admitted as algebras unless GSL-COMPARE later demonstrates genuinely independent closed composition semantics not already covered by Process/Policy/Decision/Conformance/Evidence, mathematics or typed graph machinery.

REVIEW QUESTIONS

2. Define AND_D/OR_D/NOT_D/RESOLVE_D behavior for INDETERMINATE, CONFLICT, NOT_APPLICABLE and REQUIRE_APPROVAL without accidental permission.
3. Check exceptions/precedence/delegation for authority escalation or scope leakage.
4. Check Conformance composition for false PASS through partial applicability, stale evidence or coverage gaps.
5. Check Evidence composition for double-counting, circular support, conflicting evidence, dependence-model misspecification and uncertainty propagation.
6. Check cross-algebra composition: Policy <-> Decision; Conformance <-> Evidence/Proof; Process <-> Policy; no layer may manufacture truth/authority.
7. Compare DO_NOTHING and simplification/merge alternatives.
8. Request exact missing context with EXPAND_REQUIRED rather than inventing it.
