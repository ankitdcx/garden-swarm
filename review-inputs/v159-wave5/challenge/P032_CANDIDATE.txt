Status: DESIGN-CLOSURE CANDIDATE / NO NEW SCHEMAID MINTING / NOT CANONICAL

1. ADMISSION PRINCIPLE
A candidate name is not a schema. Before machine admission every retained artifact/profile SHALL have an admission row with relation, host, owner, role, scope/currentness, status, tests and unresolved obligations. If exact host sufficiency cannot be established, return INCOMPLETE / NEEDS_SCHEMA_ADMISSION. No placeholder SchemaID is minted.

Relation evaluation is semantic, not name-based:
- DUPLICATES when no distinct semantic delta exists -> remove candidate, retain migration reference if needed.
- ALIASES when the same artifact/rule is intentionally given another qualified name -> point to canonical owner.
- REFINES when the candidate is an owner-qualified policy/profile/view that narrows/adds constraints without requiring a new persistent identity.
- EXTENDS when the candidate requires genuinely additional persistent fields/relations/lifecycle beyond the host while preserving host identity/contract.
- NEW only when no existing host can represent the required persistent semantics after full owner-field comparison.
Do not force one lexical precedence when host evidence is incomplete; choose the least ontology-expanding relation that is semantically valid and record the reason.

2. STATUS DOMAIN
For each admission row:
  existing_status = ENFORCED | CHECKED | SPECIFIED | NOT_PRESENT | UNKNOWN
  delta_status = ENFORCED | CHECKED | SPECIFIED | INCOMPLETE | NEEDS_SCHEMA_ADMISSION | NOT_PRESENT | UNKNOWN
UNKNOWN/INCOMPLETE/NEEDS_SCHEMA_ADMISSION is non-PASS for machine admission. `TEST-*` prose is SPECIFIED unless exact executable harness/result receipts are bound.

3. TRUST ALLOCATION
TrustAllocationDecision/v1 SHALL be a strict attenuation/narrowing assessment over an independently valid current parent authorization/envelope. It may restrict, condition, scope or deny. It SHALL NOT create, widen, revive or reauthorize authority. If parent grant is absent/revoked/expired -> no effective authority regardless of trust/reputation.
Relation: REFINES/EXTENDS existing PolicyDecision/AuthZ/envelope machinery pending exact host-field closure; no new authority root.

4. REPUTATION
ReputationAggregationPolicy/v1 is a qualified policy/profile over ComparePolicy + the correct owner-qualified ReputationProfile. Bare `ReputationProfile` SHALL NOT resolve across HumanCore.Identity.ReputationProfile and Capability.Economy.ReputationProfile without owner qualification.

6. CAPABILITY TRANSFER SPLIT
Reject the bare catch-all `CapabilityTransferAssessment/v1` as an admitted type.
Use distinct owner-qualified semantics:
- CTSN.DerivativeTransferAssessment (or equivalent qualified name) for model/system parent->derivative capability/safety evidence transfer, bound to derivative lineage/assurance owners.
- HRAP.HumanCapabilitySupportAssessment (or equivalent) for human learning/skill/delegation support, bound to human intent/consent/human-effect owners.
They may be profiles/views over existing hosts; new SchemaIDs require separate proof of persistent-data need.
Cross-domain target misuse is invalid.

7. CAUSAL CLOSURE RECEIPT
CausalClosureReceipt/v1 SHALL NOT duplicate CausalGraph or CausalReconstructionTrace node/edge payloads.
It is a closure/disposition receipt referencing the canonical graph/trace/evidence artifacts and qualified CLIC function outputs. It records closure status, material gaps/frontier, owner refs, authority refs, unresolved obligations, ComparePolicy and disposition. Causal edge epistemic status remains in or references the canonical causal/evidence representation.
Engine.Compare owns comparison/gap aggregation; it does not become sole causal-proof or action-authority owner.
If canonical host fields cannot express required closure metadata, only those exact missing fields are proposed as an extension.

8. INTEGRITY REPORT
IntegrityReport/v1 is a REFINES/profile view over the existing IncidentRecord/reporting lifecycle unless exact host comparison proves a distinct persistent record is necessary. Reporter-protection/merits/bad-faith semantics reuse P019/P025 owners. Channel routing binds IntegrityChannelOwner. No duplicate merits lifecycle.

9. PHYSICAL ACTION ENVELOPE
PhysicalActionEnvelope/v1 is a qualified physical-safety refinement/profile anchored to SafetyEnvelope and ControlledActuationRecord. It SHALL preserve exact device/action/force/energy/time/space/shared-resource bounds and external-interlock/compensating-control preconditions. Controlled actuation fails closed if required current envelope/interlock bindings are missing or invalid.
Until exact host-field mapping is verified, status remains SPECIFIED/NEEDS_SCHEMA_ADMISSION rather than a standalone ENFORCED schema.
