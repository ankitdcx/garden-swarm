Status: DESIGN-CLOSURE CANDIDATE / NO NEW SCHEMAID MINTING / NOT CANONICAL

1. ADMISSION PRINCIPLE
A candidate name is not a schema. Before machine admission every retained artifact/profile SHALL have an admission row with relation, host, owner, role, scope/currentness, status, tests and unresolved obligations. If exact host sufficiency cannot be established, retain the candidate as SPECIFIED with closure_status INCOMPLETE / NEEDS_SCHEMA_ADMISSION. No placeholder SchemaID is minted.

Relation evaluation is semantic, not name-based:
- DUPLICATES when no distinct semantic delta exists -> remove candidate, retain migration reference if needed.
- ALIASES when the same artifact/rule is intentionally given another qualified name -> point to canonical owner.
- REFINES when the candidate is an owner-qualified policy/profile/view that narrows/adds constraints without requiring a new persistent identity.
- EXTENDS when the candidate requires genuinely additional persistent fields/relations/lifecycle beyond the host while preserving host identity/contract.
- NEW only when no existing host can represent the required persistent semantics after full owner-field comparison.
Choose the least ontology-expanding relation that is semantically valid and record the reason. Do not invent a host when evidence is incomplete.

2. STATUS DOMAIN
Preserve the source status domain:
  existing_status = ENFORCED | CHECKED | SPECIFIED | NOT_PRESENT.
Use a separate closure_status when the inherited status/host relationship is not established:
  closure_status = RESOLVED | UNKNOWN | INCOMPLETE | NEEDS_SCHEMA_ADMISSION | BLOCKED.
For the candidate delta:
  delta_status = ENFORCED | CHECKED | SPECIFIED | NOT_PRESENT | INCOMPLETE | NEEDS_SCHEMA_ADMISSION | BLOCKED.
UNKNOWN/INCOMPLETE/NEEDS_SCHEMA_ADMISSION is not an ENFORCED/CHECKED admission. It may remain in the design as an explicitly unresolved candidate with resolution obligations. `TEST-*` prose is SPECIFIED unless exact executable harness/result receipts are bound.

3. TRUST ALLOCATION
TrustAllocationDecision/v1 is scoped to an independently valid current ParentAuthorityEnvelope / authorization machinery. Owner policy may allocate, condition, narrow or deny capabilities/actions only within that current parent envelope.
Invariant:
  EffectiveAuthorizedScope <= CurrentParentAuthorityEnvelope.
Trust/reputation SHALL NOT create a new authority root, exceed the parent envelope, revive a revoked/expired grant or bypass a hard authority/rights/safety/law condition.
If no current parent authority exists, trust alone produces no effective authority.
Exact allocation/attenuation semantics inside the parent envelope remain owner-qualified rather than one universal trust formula.

4. REPUTATION
ReputationAggregationPolicy/v1 is a qualified policy/profile over ComparePolicy + the correct owner-qualified ReputationProfile. Bare `ReputationProfile` SHALL NOT resolve across HumanCore.Identity.ReputationProfile and Capability.Economy.ReputationProfile without owner qualification.

6. CAPABILITY TRANSFER SPLIT
Reject the bare catch-all `CapabilityTransferAssessment/v1` as one admitted semantic type.
Separate owner-qualified concepts are required:
- a CTSN derivative/system transfer assessment for parent->derivative capability/safety evidence transfer, owned by the derivative lineage/assurance domain;
- an HRAP human capability support/learning assessment, owned by Human Sovereignty/Human-Effect/intent-consent domain.
The exact qualified names and canonical host schemas remain fields in their admission rows; this candidate does not mint those names as SchemaIDs. They may resolve as profiles/views over existing hosts.
Cross-domain target misuse is invalid.

7. CAUSAL CLOSURE RECEIPT
CausalClosureReceipt/v1 SHALL NOT duplicate CausalGraph or CausalReconstructionTrace node/edge payloads.
It is a closure/disposition receipt referencing canonical graph/trace/evidence artifacts and qualified CLIC function outputs. It records closure status, material gaps/frontier, owner refs, authority refs, unresolved obligations, ComparePolicy and disposition. Causal-edge epistemic status remains in or references the canonical causal/evidence representation.
Engine.Compare owns comparison/gap aggregation; it does not become sole causal-proof or action-authority owner.
If canonical host fields cannot express required closure metadata, only those exact missing fields are proposed as an extension.

8. INTEGRITY REPORT
IntegrityReport/v1 is a REFINES/profile view over the existing IncidentRecord/reporting lifecycle unless exact host comparison proves a distinct persistent record is necessary. Reporter-protection/merits/bad-faith semantics reuse P019/P025 owners. Channel routing binds IntegrityChannelOwner. No duplicate merits lifecycle.

9. PHYSICAL ACTION ENVELOPE
PhysicalActionEnvelope/v1 is a qualified physical-safety refinement/profile anchored to SafetyEnvelope and ControlledActuationRecord. It inherits and applies their existing fail-closed semantics and must preserve exact device/action/force/energy/time/space/shared-resource bounds plus external-interlock/compensating-control preconditions. If required fields cannot be represented, extend the owning host contract rather than bypass it with a detached envelope.
Until exact host-field mapping is verified, status remains SPECIFIED/NEEDS_SCHEMA_ADMISSION rather than a standalone ENFORCED schema.
