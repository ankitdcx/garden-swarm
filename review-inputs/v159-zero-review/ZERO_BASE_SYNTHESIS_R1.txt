ZR-001 — EMERGENCY SOURCE-INDEPENDENCE NORMALIZATION
Disposition: PATCH
Owner: existing emergency detector / hazard profile / evidence contract
Rule:
1. Applicable qualified hazard/profile evidence contract owns source-diversity and independence requirements.
2. If no qualified profile is available for a high-consequence emergency trigger, preserve the existing safety floor: require at least two materially independent external observations before escalation beyond baseline authority.
3. “Two sensors” is not sufficient by itself. Sources sharing a material upstream feed, controller, calibration chain, model, data path, or common-mode failure are not independent merely by count.
4. Internal urgency/model state cannot satisfy the external-hazard-evidence requirement when doing so would expand acting authority.
5. A qualified profile may require one, two, or more sources only when its evidence contract explicitly justifies that cardinality and the resulting action remains within existing authority/safety law.
6. EMG-003 is superseded in current reading by this rule; the historical text remains lineage.
Tests: common upstream feed; shared calibration; forged/stale attestations; profile with one qualified source but no authority expansion; absent profile retains >=2 materially independent external observations.

ZR-002 — CONSENT VALIDITY PROFILE OVER EXISTING OWNERS
Disposition: PATCH / NO NEW PRIMARY SCHEMA
Owner: ConsentContract + UnderstandingRecord + existing human/authority/privacy/legal gates
Rule:
1. Do not admit a new standalone persistent ConsentValidityAssessment SchemaID at this stage.
2. Define a derived machine-resolvable ConsentValidityResult/FunctionContract profile over existing artifacts.
3. Result binds subject/principal, requested action/effect/scope, authentication evidence, freshness/expiry/revocation, disclosure/explanation, UnderstandingRecord/comprehension, voluntariness/coercion evidence, jurisdiction/profile requirements, applicable independent review, material invalidators, DesignEpoch/KnowledgeSnapshot/environment, and provenance.
4. Status vocabulary: VALID_FOR_SCOPE | INVALID | UNKNOWN | INCONCLUSIVE | STALE | BLOCKED, mapped to existing result/status algebra where available rather than creating a parallel algebra.
5. Signature/authentication proves only its declared authentication properties; it never alone proves comprehension, voluntariness, legal validity, waiver, or authority.
6. Consent validity does not replace legality, rights, safety, policy, evidence, capability, or authority gates.
7. Promote to a dedicated persistent artifact only after an owner-gap/schema-admission review proves the derived profile insufficient.

ZR-003 — CONSTITUTIONALEVENT CROSS-FIELD COHERENCE
Disposition: KEEP

ZR-004 — CONSTITUTIONALEVENT NON-AUTHORIZING RESPONSE + PRIVACY-PRESERVING OBSERVABILITY
Disposition: PATCH / CLARIFY EXISTING OWNER
Owner: ConstitutionalEvent + existing Authority/Privacy/Evidence/Action owners
Rule:
1. Event existence, VETO, VIOLATION, severity, containment criteria, evidence refs, or routing never by themselves authorize containment/restriction.
2. Any executed containment/restriction must resolve to a separately valid current authorization/action/admission artifact under existing authority, scope, expiry, privacy, safety and evidence rules.

4. Event observability/query/subscription is an authority-preserving projection. Seeing an event does not grant permission to dereference protected evidence/context/identity.
5. Referenced data retains source access, consent, taint, minimization, retention and jurisdiction constraints.

ZR-005 — DERIVED ACTIVE-DEFINITION INDEX / EFFECTIVE SEMANTIC SNAPSHOT
Disposition: PATCH
Owner: release/current-reading metadata; non-normative derived index
Rule:
1. Generate a hash-bound ActiveDefinitionIndex/EffectiveSemanticSnapshot near the front of each release.
2. It maps each active anchor/package to current owner, effective source range/hash, effective version/status, aliases, superseded lineage, unresolved/deferred state and assurance dimensions.
3. The index is DERIVED_NAVIGATION_METADATA_ONLY. It cannot override the normative owner, append-only precedence, or active source bytes.
4. If the index conflicts with normative source, the source wins and the index is INVALID/STALE until regenerated.
5. Retained staged/historical review prose is explicitly HISTORICAL/INACTIVE in the index so a new reader/parser cannot mistake it for current release status.
6. Regeneration must be deterministic from release source + current-reading rules.
