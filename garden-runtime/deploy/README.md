# Runtime deployment

**IMPLEMENTATION**: native Docker/Compose files. **EXPERIMENTAL**: separately deployed Worker gate subset in `worker-site/`. These are different implementations; an online Worker does not mean the Rust backend has been hosted.

Native local deployment: from `garden-runtime`, run `docker compose -f deploy/compose.yaml build`, then `docker compose -f deploy/compose.yaml up ingress`. Open `http://127.0.0.1:8080`. The controller and external Rust gate run in a read-only container with a private root-owned state volume. Only SETUID/SETGID remain so the trusted controller can drop advisory child processes to UID 65534. The gate's network is internal-only and has no published ports. A separate UID 65534 transport container joins the internal and host-facing networks and publishes only host localhost. It forwards solely to the fixed `gate-console:8080` target, with at most 16 active connections, 2 MiB per direction and 30 seconds per connection; callers cannot select a host or port. This transport has no state, policy or secret mounts and logs no request bytes, but is trusted for credentials in transit. Optional advisory containers use UID 65534, no network, no capabilities, and no gate/state/policy mounts. Model outputs remain proposals. Docker daemon/host/controller compromise remains outside this boundary.

The default advisory image uses rule-based fallback. No model is silently downloaded and no paid endpoint configured. The Console supports the fixed WASM model-as-data route described in the runtime README. Native adapters can run separately as observations in an isolated advisory container; mounting model assets does not connect them to the Console or confer tool authority. The Console Python shim is rule-only and ignores all native model environment settings. No model must receive the controller's process environment, state directory, Docker socket or gate credentials.
