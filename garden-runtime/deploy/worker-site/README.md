# Garden Worker gate subset

Status: **EXPERIMENTAL**. This is a real server-side execution boundary and a separate implementation from the native Rust gate. It is not Rust/Wasm parity and does not promote any candidate Garden rule.

The public demo issues bounded anonymous demo identities and separate human/agent bearer credentials. Agent requests use `/api/proposal`. Human confirmation uses `/api/run`, which the agent credential cannot call. Immutable policy permits a bounded calculator, D1-backed notes, a stored mock outbox restricted to `invalid.test`, and stored test ledger entries. No email or money is sent. Agent/model output cannot register verification, alter policy, gain successor authority, or select a gate administrator.

D1 committed signed decision records **are** the note/outbox/ledger mock effects. An atomic guarded INSERT checks authority expiry/revocation and a maximum 64 decisions per session at the actual commit boundary. Unique nonce/proposal/sequence constraints reject replay and concurrent stale state. Receipts are HMAC authenticated and chained per session. This establishes log integrity under the trusted host/key assumption, not the truth of source claims. Anonymous sessions expire in one hour. A total 1,000-session public demo budget bounds storage; exhausting it can deny service until an authorized maintenance release.

No open model is hosted inside this Worker. The native local Rust/Python runtime contains open-model adapters. The Worker planner is deterministic. General semantic truthfulness, open-ended QSE and epistemic independence are explicitly unresolved; its deterministic tool-contract checker does not claim those capabilities. Production identity binding, signed-user consent, robust general external-effects transactions, administrative maintenance, and protection against a compromised hosting owner are outside this deployed subset.

Run `npm ci`, `node --test tests/worker.test.mjs`, `bash scripts/build.sh`, and `node scripts/validate-artifact.mjs`. Schema is in `db/schema.ts`; generated Drizzle migrations are preserved under `drizzle/`. Production state is injected through logical D1 binding `DB`, and receipt signing through secret `GARDEN_RECEIPT_KEY` (32+ bytes). Never put real secrets in the source tree. Dependency licenses: drizzle-orm/drizzle-kit Apache-2.0; native runtime Apache-2.0. Generic dependency provenance remains in package-lock.json.

There is no model execution or kernel-update route. Any update is a source diff, independent attack, regression run, and owner-controlled deployment. The hosting owner can still replace the server code: host compromise is a residual trust assumption, not solved by a receipt signature.
