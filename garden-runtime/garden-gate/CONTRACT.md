# Garden gate wire contract (IMPLEMENTATION 0.1)

Run `garden-gate --policy PATH --state-dir DIR --sandbox-dir DIR`. Input/output are one JSON object per line, with duplicate object keys rejected at every depth. Environment requires separate `GARDEN_CONTROL_TOKEN` and `GARDEN_RECEIPT_KEY`, each at least 32 bytes. `GARDEN_BOUND_ACTOR_ID` binds the authenticated broker principal for this gate process (sample default `planner-demo`); a proposal cannot choose a different registered actor. Only the trusted server receives these credentials. Model subprocesses must have separate filesystem/UID/container access; JSON gating alone is not OS isolation. State, tool sandbox and policy/kernel files must occupy separate locations. The bootstrap sandbox/state directories are mode 0700.

Public operations: `status`, `digest` with `proposal`, `evaluate` with `proposal`, `execute` with `proposal`, `receipt_check` with `receipt`.

Proposal example:

```json
{"id":"job-1","nonce":"nonce-1","actor_id":"planner-demo","delegation_id":"demo-delegation","policy_version":"garden-implementation-0.1","tool":"calculator","args":{"op":"add","a":2,"b":3},"claims":[],"unknowns":[],"human_effect":false,"assessment_ids":{"verification":null,"qse":null,"truthfulness":null,"human_effect":null},"successor_of":null}
```

Allowed tools and exact argument fields: `calculator`: `op` (`add`,`subtract`,`multiply`,`divide`), finite numeric `a`,`b`; `sandbox_read`: `path` (one plain filename); `sandbox_write`: `path`,`content` (maximum 8192 bytes); `mock_email`: `to`,`subject`,`body` (record only, never sent); `mock_ledger`: `from`,`to`,`amount_cents` (positive bounded integer, existing test accounts). File paths allow ASCII letters, digits, hyphens, underscores and nonleading dots only. Slashes, backslashes, dot-prefixes, symlinks, multiply linked files and nonregular files are rejected; reads are nonblocking and bounded to 8192 bytes. Only calculator and sandbox_read are classified read-only. Mutating tools require `human_effect:true` and all four assessments. Human effect cannot be suppressed by a proposal field.

Proposal digest = SHA-256 over compact serde JSON serialization of the typed proposal, replacing `assessment_ids` with four null values. Every other semantic field is bound. Use `digest` operation for exact bytes/digest; object serialization from another language can differ.

Trusted control operations require `control_token`: `register_assessment` with `assessment`; `register_evidence` with `evidence`; `revoke` with `delegation_id`. No policy update operation exists.

Assessment schema:

```json
{"id":"verification-1","proposal_digest":"HEX","reviewer_id":"verifier-demo","kind":"verification","status":"PASS","findings":[],"covered_dimensions":[],"material_omissions":[],"policy_version":"garden-implementation-0.1","expires_at":4102444800}
```

Kinds: `verification`, `qse`, `truthfulness`, `human_effect`. Status: `PASS`,`FAIL`,`UNKNOWN`. QSE PASS requires covered dimensions `missing_questions`,`missing_variables`,`alternative_representations`,`omissions`,`boundary_attacks`,`rule_conformant_attacks`,`counterfactual_redesigns`,`integration_failures`. Human-effect PASS requires `rights`,`consent`,`privacy`,`authority`,`safety`,`law`,`evidence`,`explanation`. Findings and material omissions must be empty to permit. Registration establishes integrity of a trusted assessment channel, not the truth of its contents. Consequential verifier must have different family, lineage and controller from proposer; registries and role labels do not establish genuine epistemic independence by themselves.

Evidence schema: `{"id":"e-1","claim_id":"c-1","status":"SUPPORTED","source_anchor":"...","content_sha256":"64 hex chars"}`. `register_evidence` additionally requires a top-level `content` string, at most 8192 UTF-8 bytes, whose SHA256 exactly matches `content_sha256`. The gate stores a protected content-addressed blob under its state directory and rechecks existence/hash when evaluating a claim and immediately before effect. Metadata without corresponding content cannot pass. Status may also be `CONFLICTING` or `UNKNOWN`. Proposal claim schema: `{"id":"c-1","evidence_ids":["e-1"]}`. Empty, absent, corrupt or conflicting evidence yields quarantine; inference is never converted to proof. Content integrity and an operator-supplied source anchor do not establish source-origin authenticity, empirical truth, or logical support of the linked claim; these remain substantive verification obligations.

Response contains `ok`, `decision` (`ALLOW`,`DENY`,`QUARANTINE`), `reasons`, optional `result`, `receipt`. Execute consumes bound-principal proposal IDs/nonces even when denied; evaluate is a dry run. Impersonated principals do not populate the mutable identity/nonce registry. Allow is bounded to the exact registered actor/tool/proposal/policy. Current implementation denies replay instead of returning canonical EXE-005's cached receipt: this is a conservative implementation profile, not full EXE-005 conformance. Receipts are HMAC authenticated and hash chained; these properties establish record integrity, not truth or external effect certainty. Execute has full decision/action receipts; evaluate, control operations and malformed/unknown requests have event audit receipts. Status, digest and receipt integrity queries have no receipt. The gate enforces a bounded journal (default 10000 events); after its budget is exhausted, it denies further state-changing/audited requests without growing storage, while introspection remains available.

One gate writer owns state; restart validates signed state and journal. Requests reserve authority/resource counters and persist a pending marker before effect, then recheck authorization, expiry and all applicable assessments. After any filesystem/evidence validation, a final minimum-deadline sweep admits the exact bounded tool call at the receipt's `admission_timestamp`. The receipt's later `timestamp` records receipt creation. Authority is required at adapter admission; this profile does not authorize long-lived external work after lease expiry. Future external adapters need their own leased/cancellable transactions or point-of-effect deadline support. Delegation ancestry is attenuated, acyclic, not self-delegating and bounded by the current configurable depth profile (default five). Revocation of any ancestor invalidates descendants. An interrupted prepared operation remains quarantined at startup rather than silently retried; the operator must investigate and recover it. This provides replay containment and explicit crash uncertainty, not general transactional exactly-once external effects. HMAC logs cannot prevent a privileged operator from restoring an entire older authenticated state/journal pair; external antirollback anchoring is a residual need.

The example policy is a synthetic demonstration authority over these harmless tools. Its long sample expiry and structural reviewer labels do not certify genuine consent, evidence truth, model-family independence or a production authority-management process. The trusted broker must obtain applicable human confirmation and narrow deterministic reviews; it must not register arbitrary model outputs as trusted PASS records. Assessment control-token compromise, host/kernel compromise, incorrect semantic effect classification and previously unknown collusion remain outside the demonstrated containment guarantee.
